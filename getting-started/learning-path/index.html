Suggested Learning Path

A roadmap through the material based on your experience level. Most pages are outlines. Each one will grow a C# sample, with a companion .cs file when the sample is longer than about 30 lines.

Path 1: New to Software Engineering

Duration: 9-12 months (part-time)

This path ends when you can build a console app and a small API with authentication, authorization, Entity Framework, and tests. Web UI, Windows, mobile, MCP, and the SaaS project are Path 4.

Phase 1: Workstation (Weeks 1-2)

  1. Prerequisites - Verify you're ready
  2. Workstation Setup - Get your tools
  3. AI-Assisted Development - Terms and techniques you will use the rest of the way
  4. Git Installation - Version control on day one
  5. Branching and Pull Requests - How a change lands on main

Phase 2: Foundations (Months 1-2)

  1. Big O - Start thinking about complexity
  2. Data Structures - Arrays through trees
  3. OOP Principles - Foundation for C#
  4. Error Handling - What a caller is owed when something fails
  5. HTTP and the Web - Read this before any API
  6. Security Concepts - The failures a feature developer meets
  7. Authentication and Authorization - Who the caller is, and what they may do

Phase 3: C# (Months 3-4)

  1. Getting Started - Your first program
  2. Projects and Solutions - How a program is built
  3. The rest of Language Basics - Types, nullability, exceptions, collections, delegates, disposal
  4. LINQ - Essential for productivity
  5. Async - Modern C# requirement

Phase 4: The Platform, then a Console App (Month 5)

  1. The .NET Platform - Host, dependency injection, configuration, logging, HTTP clients
  2. Console Apps - The smallest thing you can ship
  3. Command-Line Parsing - A real command

Phase 5: Data (Months 5-6)

  1. SQL Fundamentals - The language
  2. Indexes and Query Plans - Why a query is fast or slow
  3. Transactions and Isolation - Atomic changes
  4. Entity Framework - Then modeling, change tracking, and transactions
  5. Repository - And why DbContext is already a unit of work

Phase 6: Tests (Month 6)

  1. Debugging - Reproduce, narrow, fix, prove
  2. Testing Strategy - What each kind of test proves
  3. TUnit Project Setup - The runner this site uses
  4. Unit Testing and Mocking - TUnit and TUnit.Mocks
  5. ASP.NET Core Tests - The API in-process
  6. Reqnroll - A feature file that runs as a TUnit test

Phase 7: A Secured API (Months 7-10)

  1. Web APIs - Endpoints, validation, errors, OpenAPI
  2. Choosing a Scheme - Cookie, JWT, or OpenID Connect
  3. JWT and Authorization - Including a check against a specific row
  4. Rate Limiting - Slow a caller down
  5. Observability and Health Checks - Logs, traces, and a readiness probe
  6. Secrets and Kestrel and HTTPS - Nothing secret in the repository, and TLS in front

Phase 8: How the Work Is Done (Ongoing)

  1. Architecture - Where each app type sits
  2. Code Review - Including a review of generated code
  3. Verification - The assistant does not replace the diff

Path 2: Experienced Developer, New to .NET

Duration: 3-5 months (part-time)

Same destination as Path 1: a console app and a secured API. Skip the foundations you already have. Use the AI-assisted development section as you go.

Phase 1: C# and the Platform (Weeks 1-3)

  1. Language Basics - Skim for syntax, then read nullability and projects and solutions
  2. LINQ, async, and records
  3. The .NET Platform - Host, dependency injection, configuration, logging, HTTP clients
  4. Console Apps - One small tool

Phase 2: Data and the API (Weeks 4-8)

  1. Entity Framework - Modeling, change tracking, transactions
  2. Web APIs - Including validation, Problem Details, and rate limiting
  3. Choosing a Scheme, JWT, and authorization
  4. Observability

Phase 3: Tests (Weeks 6-8, alongside the API)

  1. TUnit Project Setup, unit tests, and mocks
  2. ASP.NET Core tests
  3. Reqnroll - Scenarios on the TUnit runner

Continue with Path 4.

Path 3: Senior Engineer → Management

Duration: Ongoing

Immediate Focus

  1. Career Ladder - Understand the transition
  2. Individual Contributor → Manager - Specific guidance
  3. One-on-Ones - Your most important tool
  4. Giving Feedback - Practice immediately

First 90 Days

  1. Hiring - If you're building a team
  2. Team Building - Culture matters
  3. Skill Matrices - Know your team

Ongoing Development

  1. Stakeholder Management - Working with others
  2. Technical Writing - Clear communication
  3. Manager → Director - Next level

Path 4: Full-Stack C# Applications

Duration: 6-9 months (part-time), after Path 1 or Path 2

The client rule for this path: the UI renders and calls the API. Business rules stay on the server.

Web

  1. Blazor - Components, forms, and render modes
  2. Blazor authentication - A cookie, not a token in the browser
  3. bUnit - Component tests on TUnit

Windows

  1. Clients - MVVM, XAML, and the shared API client
  2. WinUI 3 - Windowing, packaging, and authentication

Mobile and WebAssembly

  1. Uno Platform - Targets, platform-specific code, and device authentication

MCP

  1. MCP Servers - Tools, resources, and prompts
  2. Hosting - stdio for a local client, HTTP for a remote one
  3. Using MCP - The client side of the same protocol

Capstone

  1. Building a SaaS - The applied project. Its chapters link back to the reference pages.
  2. Redis, SignalR, and background services show up as the project needs them
  3. Patterns - Reference while you build. Decorator and CQRS are the two taught beyond the repository

How to Learn Effectively

  1. Don't just read - Build things with what you learn
  2. Take notes - In your own words
  3. Teach others - Best way to solidify knowledge
  4. Be patient - Mastery takes time
  5. Review generated code - An assistant can draft a sample. You still read the diff and run the tests

Pick the path that fits your situation and get started. You can always adjust as you go.
